# ТЕХНИЧЕСКОЕ ЗАДАНИЕ (ТЗ)
## на разработку веб-приложения «WordForge» (Интеллектуальная словесная игра с генеративным ИИ и мультиплеером)

---

## 1. Общие сведения

* **Наименование системы:** Веб-приложение «WordForge».
* **Назначение:** Интерактивная многопользовательская словесная игра в концепции Wordle с динамической генерацией тем посредством больших языковых моделей (LLM), синхронным многопользовательским PvP-режимом в реальном времени, развитой системой геймификации и социальным взаимодействием.
* **Целевая аудитория:** Пользователи любого возраста, интересующиеся словесными головоломками, расширением словарного запаса и соревновательными интеллектуальными играми.
* **Языки интерфейса и контента:** Русский (`ru`), Английский (`en`).

---

## 2. Цели и задачи проекта

* **Цель:** Создание масштабируемого, автономного веб-сервиса без использования тяжелых внешних веб-фреймворков, реализующего соревновательный игровой процесс на базе классической механики отгадывания слов с высокой реиграбельностью за счет интеграции генеративного искусственного интеллекта.
* **Ключевые задачи:**
  1. Реализовать независимый веб-сервер и REST API на нативном модуле Node.js `node:http`.
  2. Разработать кросс-движковую абстракцию БД (SQLite для локальной разработки и PostgreSQL для продакшена).
  3. Спроектировать отказоустойчивый шлюз интеграции с LLM с поддержкой множества провайдеров (Groq, Gemini, OpenAI, Anthropic), каскадным переключением моделей (fallback) и аварийным локальным банком слов.
  4. Создать WebSocket-сервер для синхронных дуэлей на 2–4 игроков в реальном времени с защитой от раскрытия ходов.
  5. Реализовать клиентскую часть на нативном JavaScript (SPA) с кастомным реактивным рендерингом без внешних библиотек.
  6. Внедрить систему геймификации: расчет опыта (XP), уровни, достижения, адаптивную сложность и глобальные лидерборды.

```
│  ┌──────────▼───────────┐                     ┌───────────▼─────────┐  │
│  │    AI Gateway        │                     │   Data Access Layer │  │
│  │ (Groq/Gemini/OpenAI) │                     │ (SQLite/PostgreSQL) │  │
│  └──────────────────────┘                     └─────────────────────┘  │
└────────────────────────────────────────────────────────────────────────┘
```

* **Backend Runtime:** Node.js (v22+ LTS).
* **Сетевой стек:**
  * HTTP-сервер: встроенный модуль `node:http` (нулевые сторонние зависимости для HTTP).
  * WebSockets: библиотека `ws` для сетевых дуэлей.
* **Базы данных (Dual-Dialect DAL):**
  * Local/Dev: встроенный модуль `node:sqlite` (`DatabaseSync` с включенным режимом WAL и таймаутом занятости 5000 мс).
  * Production: PostgreSQL через драйвер `pg` (пул соединений, нативная поддержка SSL).
* **Безопасность и криптография:** нативный модуль `node:crypto` (`scrypt` с 16-байтным солью для хеширования паролей, `HMAC-SHA256` для stateless JWT-токенов).
* **AI Провайдеры:** Groq API (основной продакшен), Google Gemini REST API v1beta, Anthropic API, OpenAI API.
* **Frontend:** Чистый HTML5, CSS3 (кастомные свойства, CSS Grid, Flexbox, темная/светлая темы), Vanilla JavaScript (ES Modules).

## 5. Функциональные требования

### 5.1. Аутентификация, профиль и безопасность
* **Регистрация / Вход:**
  * Валидация логина: 3–20 символов (`[A-Za-z0-9_.-]`), регистронезависимая уникальность.
  * Пароли: от 8 до 100 символов, криптостойкое хеширование `scrypt` с индивидуальной солью.
  * Авторизация через заголовок `Authorization: Bearer <token>` с проверкой подписи HMAC-SHA256 и времени жизни (`TOKEN_TTL_MS`, по умолчанию 30 дней).
* **Профиль игрока:**
  * Отображение ранга, текущего XP и шкалы прогресса до следующего уровня по формуле:
    $$\text{Уровень } n \text{ начинается при } 60 \times (n - 1)^2 \text{ XP}$$
  * Статистика: общее число игр, винрейт, текущий и рекордный винстрик, стрик ежедневных игр, гистограмма распределения числа попыток при победе, список любимых тем.

### 5.2. Игровой движок и механики
* **Оценка догадки (Алгоритм Wordle):**
  * Возврат цветовой маски фиксированной длины:
    * `g` (green) — буква угадана и стоит на правильном месте.
    * `y` (yellow) — буква есть в слове, но находится на другой позиции (с корректным учетом повторяющихся букв через счетчик остатка).
    * `b` (black/gray) — буквы нет в слове.
* **Валидация догадок:**
  * Орфографическая эвристика на недопустимые сочетания согласных/гласных подряд.
  * Проверка наличия в локальной БД слов или таблице валидного словаря `dictionary`.
  * При отсутствии слова в кэше — фоновый запрос к ИИ для валидации сленга, имен собственных и лора с занесением вердикта в кэш.
* **Калькуляция очков и опыта (Scoring):**
  * Базовая формула победы:
    $$\text{Base} = 100 + (\text{MaxAttempts} - \text{Attempts}) \times 25 + (\text{Length} - 5) \times 10 - (\text{Hints} \times 20)$$
  * Бонус за скорость в режиме на время (до 60 дополнительных очков).
  * Итоговый счет умножается на модификатор режима: `Classic` ($\times 1$), `Timed` ($\times 1.25$), `Hardcore` ($\times 2$), `Describe` ($\times 1$), `Daily` ($\times 1.5$), `Room` ($\times 1.25$).
  * XP начисляется в размере $50\%$ от заработанных очков (при поражении — фиксированные 5 XP за участие, 0 XP при преждевременном выходе).

### 5.3. Игровые режимы
1. **Classic:** 6 попыток, настраиваемая длина (4–8 букв или случайная), доступно до 3 подсказок (-20 очков за каждую).
2. **Timed:** Лимит времени 180 секунд на раунд, 6 попыток, динамический таймер с визуальным предупреждением на последних 30 секундах.
3. **Hardcore:** 4 попытки, подсказки отключены, двойной множитель очков.
4. **Describe:** 6 попыток, смысловое описание (clue) отображается сразу перед первым ходом.
5. **Daily Word:** 5-буквенное слово, единое для всех игроков мира в текущие сутки UTC. Ровно одна попытка в день.
6. **Room (PvP):** Синхронный поединок для 2–4 участников в отдельной комнате.

### 5.4. Интеграция с LLM и пайплайн генерации слов
* **Автоматическое разрешение тем (Bilingual Canonical Resolution):** LLM преобразует пользовательский ввод на любом языке в канонический франшизный лор и отдает слова и подсказки strictly на целевом языке (`ru` или `en`).
* **Критерии к генерируемым словам:**
  * Только словарные формы существительных или каноничные имена собственные/термины.
  * Исключение общих бытовых предметов («failed», «pocket», «street», «jacket»).
  * Точное соблюдение длины слова (от 4 до 8 символов).
  * Генерация емкой подсказки (до 90 символов) без раскрытия самого слова и без служебных префиксов («Артефакт:», «Локация:»).
* **Многоуровневые подсказки (makeHint):**
  * Уровень 1: Атмосферная загадка/роль в теме.
  * Уровень 2: Канонический сюжетный факт с учетом уже сделанных игроком попыток.
  * Уровень 3: Прямая наводка с гарантированным указанием первой буквы слова.
* **Разбор после завершения игры (explainWord):** вывод определения слова, этимологии/истории происхождения и контекстного примера использования.
* **Отказоустойчивость и кэширование:**
  * Дедупликация параллельных запросов на генерацию через `inflightByTheme`.
  * Фоновый разогрев (`prewarm`) при наборе названия темы в интерфейсе.
  * Защита от сбоев API: аварийный оффлайн-банк на ~150+ слов при недоступности провайдеров.

### 5.5. Мультиплеер в реальном времени (WebSockets)
* **Протокол взаимодействия:**
  * Клиент $\to$ Сервер: `auth`, `room:create`, `room:join`, `room:start`, `room:guess`, `room:leave`.
  * Сервер $\to$ Клиент: `auth:ok`, `room:state`, `room:started`, `room:guessResult`, `room:guessRejected`, `room:progress`, `room:finished`, `room:error`.
* **Правила дуэли:**
  * Комната создается с уникальным 5-значным кодом (исключены визуально схожие символы `0`, `O`, `1`, `I`).
  * Вместимость: от 2 до 4 игроков. Длительность раунда: 5 минут.
  * Игроки отгадывают одно загаданное слово. Соперники видят прогресс друг друга (мини-сетки с цветными блоками `g`/`y`/`b`), но буквы остаются скрытыми до конца матча.
  * Раунд завершается мгновенно при первой победе одного из игроков либо по истечении общего таймера.
  * Reconnect Grace Period: при разрыве WebSocket-соединения игроку дается 20 секунд на перезагрузку страницы с автоматическим восстановлением состояния сессии.

### 5.6. Адаптивная сложность и динамическая калибровка
* **Адаптивный подбор (Adaptive Difficulty):** анализ последних 10 игр пользователя:
  * Винрейт $\ge 80\%$ и среднее число попыток $\le 3.5 \implies$ автоматический выбор сложных слов (сложность 3).
  * Винрейт $\le 40\% \implies$ выбор простых слов (сложность 1).
  * В остальных случаях $\implies$ средняя сложность (сложность 2).
* **Самообучение пула слов (Calibration):** после каждого завершенного раунда сложность слова в таблице `words` автоматически пересчитывается на основе реальных действий (победа за $\le 2$ попытки снижает сложность слова до 1; поражение, сдача или $\ge 5$ попыток поднимают сложность слова до 3).

### 5.7. Социальные функции и рейтинги
* Каталог пользовательских тем со счетчиком сыгранных раундов и системой лайков.
* Три независимых лидерборда:
  * Недельный топ (по сумме очков за последние 7 дней).
  * Общий зачет за все время.
  * Топ ежедневного слова (ранжирование: статус победы $\to$ очки $\to$ число попыток $\to$ время решения в миллисекундах).

## 6. Нефункциональные требования

### 6.1. Производительность и масштабируемость
* Время ответа локального REST API: не более 50 мс для кэшированных операций.
* Таймаут сетевых запросов к LLM API: жесткий лимит 20 000 мс (`AbortSignal.timeout(20_000)`).
* Ограничение частоты запросов (Rate Limiting, In-Memory Sliding/Fixed Window):
  * Авторизация (`/api/auth/*`): 10 запросов в минуту на IP-адрес.
  * Отправка догадок (`/api/games/:id/guess`): 90 запросов в минуту на пользователя.
  * Запросы к ИИ (подсказки, разборы, генерация): 25 запросов в минуту на пользователя.
  * WebSocket-сообщения: не более 40 сообщений за 10 секунд на соединение.

### 6.2. Безопасность
* Наличие строгих политик безопасности в HTTP-заголовках:
  * `Content-Security-Policy`: ограничение источников скриптов, стилей (`Google Fonts`), запрет фреймов (`frame-ancestors 'none'`).
  * `X-Content-Type-Options: nosniff`.
  * `X-Frame-Options: DENY`.
  * `Referrer-Policy: no-referrer`.
* Защита от Prompt Injection: пользовательские названия тем экранируются через регулярные выражения (`\p{L}\p{N} '\-`) и обрезаются до 40 символов. В системном промпте входные данные явно изолированы как сырые текстовые данные, а не инструкции.
* Ограничение входящих тел запросов: лимит 64 КБ на JSON-пакет (`Request body too large`).

### 6.3. Интерфейс и доступность
* Поддержка стандартов W3C WAI-ARIA (роли `grid`, `gridcell`, `status`, `alert`, `radiogroup`).
* Полная адаптивность: корректное отображение на дисплеях шириной от 320 px до 4K.
* Поддержка медиазапроса `prefers-reduced-motion: reduce` (отключение задержек анимаций штампа букв и тряски строк).
* Поддержка ввода как с физической клавиатуры, так и через экранную сенсорную раскладку.

## 8. Критерии приемки проекта

1. **Базовый игровой цикл:** пользователь может зарегистрироваться, настроить параметры, сыграть раунд и получить валидацию каждой догадки в строгом соответствии с правилами Wordle.
2. **Работа ИИ:** ввод произвольной уникальной темы (например, «Ведьмак», «Кибербезопасность») генерирует корректный список каноничных терминов без сбоев сервера. При отключении интернета/API игра бесшовно откатывается на встроенный вордбанк без падения процесса.
3. **Мультиплеер:** двое пользователей из разных браузеров/вкладок могут подключиться по коду в одну комнату, начать дуэль и соревноваться в реальном времени с корректным определением победителя.
4. **Сохранение состояния:** статистика, прогресс опыта, уровни и заработанные достижения корректно сохраняются в базе данных и переживают перезапуск сервера.
